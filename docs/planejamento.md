# Planejamento do repositório

## Objetivo

Organizar projetos acadêmicos e pessoais em um portfólio público, com documentação curta e clara para cada projeto.

## Organização

- `index.html`: página inicial do portfólio.
- `assets/css/`: estilos do site.
- `projetos/`: uma pasta por projeto, cada uma com seu próprio README.
- `docs/`: planejamento e documentação geral.
- `.github/workflows/`: automação de publicação do GitHub Pages.

## Boas práticas de versionamento

1. Manter mudanças pequenas e relacionadas.
2. Usar mensagens de commit objetivas, como `feat: adiciona seção de projetos` ou `docs: atualiza instruções do EcoGrow`.
3. Revisar os arquivos alterados antes de publicar.
4. Atualizar o README do projeto quando seu objetivo, uso ou tecnologias forem definidos ou alterados.

## Próximas etapas

- Adicionar repositórios, capturas de tela e detalhes técnicos dos projetos quando estiverem disponíveis.
- Completar os READMEs com tecnologias, funcionalidades, instruções de execução e autoria.
- Revisar a página após cada atualização e manter os links funcionando.
- Confirmar a publicação em **Settings → Pages** e no workflow em **Actions**.
